Verified Safe-Corridor Cooperative Safety Network

Safety ownership

Local radar and the deterministic safety engine can raise risk. Peer data can add a conflict but cannot clear a valid local radar hazard. Roadside and AI layers can make the system more cautious, not silently less cautious.

Non-negotiable invariant

Loss of V2V, camera, dashboard, fog node or internet must not suppress a valid local radar alert.

Core calculation

The number that drives the warning

D_required = v × t_reaction + v² / (2 × a_safe) + D_buffer

What goes into it?

v current vehicle speed · t_reaction assumed response time · a_safe conservative validated deceleration · D_buffer extra margin.

What the system outputs

M = D_verified − D_required. As the margin falls, the system can move from normal → advisory → restricted → emergency, subject to site rules.

How the pieces work together

Interactive feature explorer

Radar-first local loop

Radar is the primary local ranging layer. Track objects, estimate clear distance and feed the stopping envelope. Camera/thermal evidence may confirm or classify, but cannot veto a valid radar conflict simply because it sees nothing.

Hazard Capsule

A compact cooperative message carries the hazard type, relative distance/speed, route or segment context, uncertainty, timestamp/age, expiry and evidence. It is awareness data, not a brake command. Stale or irrelevant messages expire.

Virtual Block + Movement Token

A blind segment moves through states such as CLEAR → RESERVED → OCCUPIED → UNCERTAIN → CLOSED. A Movement Token coordinates who enters and who waits using position, speed, load, grade, road width and stopping margin. Uncertainty fails closed.

Road Guardian / MOR node

Strategic roadside nodes measure current visibility and environmental context. The source documents caution that local visibility measurements need calibration and may not represent the entire road. Forecasting should only be enabled after site-labelled validation.

AI has a supporting role

AI can assist object classification, fog trend analysis, road-segment risk scoring, anomaly detection and near-miss analytics. The immediate safety state remains deterministic and replayable rather than being owned by an opaque model.

One decision, not a dashboard explosion

Example: ⚠ SLOW DOWN · Safe Speed 8 km/h · Clear 18 m · Required 25 m · Truck Ahead 18 m. The driver should understand the action and the reason quickly.

Dashboard

2D road map, truck status, fog zones, hazards, safety margin, communication health and event history.

Replay / evidence

Store timestamp, location, speed, hazard, safety margin, sensor state and communication state so events can be inspected later.

Engineering honesty

Known flaws, limits and open risks

These are deliberately visible. A strong SIH solution should explain what is not proven yet.

LIMIT 01 · HARDWARE

Prototype sensors are not mine-rated

Student development hardware does not prove vibration, dust, rain, temperature, EMC, range or long-term reliability. Production needs ruggedized and appropriately qualified hardware.

LIMIT 02 · BRAKING

BrakeTwin needs real vehicle evidence

Safe deceleration is not a universal constant. Vehicle type, payload, grade and surface matter. Production values require measured and validated braking data.

LIMIT 03 · RADAR

Radar can still fail

Blocked, misaligned or false tracks are possible. The architecture therefore needs self-test, track consistency checks, conservative fallback and service rules.

LIMIT 04 · FOG

Fog prediction is not guaranteed

Current visibility can be measured. A useful nowcast requires site-labelled data and calibration. One roadside node cannot represent every part of a mine road.

LIMIT 05 · LOCALIZATION

GNSS can be wrong or ambiguous

A wrong route branch can corrupt road context. The safety design should shorten the trusted corridor or impose a conservative cap rather than trust uncertain localization.

LIMIT 06 · COMMUNICATION

V2V data can be stale

Packets can arrive late, disappear or describe an old hazard. Sequence, timestamp, TTL and uncertainty handling are required. Local radar remains authoritative for local conflicts.

LIMIT 07 · HUMAN FACTORS

Too many alerts can become noise

HMI needs field testing for alarm timing, wording, sound, vibration and operator acceptance. A technically correct warning can still fail if drivers cannot act on it quickly.

LIMIT 08 · SAFETY CASE

This is not safety certification

The uploaded NEXORA dossier explicitly frames the work as an engineering proposal, not safety certification. Production motion-control integration needs formal hazard analysis, validation and OEM/site approval.

LIMIT 09 · SCOPE

Prototype is advisory

We are not claiming a fully autonomous dumper. Direct throttle, retarder or hydraulic braking is outside the SIH prototype boundary.

Team explanation

Explain it in one minute

0–10 sec
Problem: Fog hides trucks, obstacles, workers and blind curves. A camera-only reaction can happen too late.
10–25 sec
Our answer: Each vehicle builds a verified safe corridor using local radar and supporting evidence. It compares that corridor with the distance needed to stop.
25–40 sec
Cooperation: Other vehicles and roadside nodes share compact hazard/visibility information, so a truck can receive useful awareness before it sees the hazard.
40–50 sec
Blind curves: A Virtual Block and Movement Token prevent conflicting entries. Uncertainty fails closed.
50–60 sec
Key safety promise: Network loss does not equal safety loss. Local radar and the deterministic safety loop remain active.
